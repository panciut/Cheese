# Trentingrana Sensory Captioning

End-to-end pipeline that turns raw sensory-panel data on **Trentingrana** cheese
(expert free-text comments + photographs of cheese wheels) into a clean
image–caption dataset, then trains and benchmarks several image-captioning
architectures on it.

This is the codebase for **AI4FQC — Project 07 `GRANA_Captioning`**.

---

## 1. Objective

Italian cheese panels score wheels on seven **sensory attributes** and leave
short free-text comments. The goal is a model that, given photographs of a
cheese wheel, generates a faithful Italian sensory description for a given
attribute (e.g. *"Il formaggio ha un profumo di panna."*).

The project has two parts:

- **Step 1 — Dataset construction.** Join thousands of BMP photographs to the
  panelists' Excel comments, then clean, normalize and rewrite the free text
  into consistent, attribute-anchored captions. Output:
  `data/final/captions_final.csv` (≈38.4k training rows).
- **Step 2 — Modeling & evaluation.** Train six encoder–decoder captioning
  architectures (each runnable frozen or fine-tuned), plus four non-trained
  baselines, and score them with eight complementary metrics.

The seven attributes are: **Aroma, Colore della Pasta, Profumo, Sapore,
Spessore della Crosta, Struttura della Pasta, Texture**.

Each cheese wheel is photographed in two **views**: `Fetta` (a slice) and
`Grana` (a close-up of the paste). Both views feed every model.

### Where the starting dataset goes

The pipeline expects the raw inputs in two specific locations under `data/`:

- **Panelist comments** → `data/GT commenti liberi/` — the Excel workbooks
  (`Commenti TOT_2018.xlsx` and the 2019/2020/2021 files) plus the `codifiche/`
  codebooks (dairy ↔ product-code map, session dates). This folder is committed.
- **Images** → `data/TrentinGrana/` — the BMP photographs, organized in
  `year/session` subfolders exactly as delivered. This folder is **gitignored**
  (too large for the repo), so you must place it yourself before running the
  pipeline.

`data/images_flat/` is **not** an input: it is generated by `build_dataset.py`
(phase 0) as a deduplicated flat copy of `data/TrentinGrana/`, and is also
gitignored.

## 3. Step 1 — Dataset construction pipeline

The pipeline goes from raw data to the final dataset in **11 ordered phases**.
Each script lives in `scripts/`, reads from `data/`, and writes both its output
and an audit report. The guiding principle throughout: **do everything
deterministically that can be done deterministically; use an LLM only for the
genuinely hard rewriting.**

| # | Phase | Script | Output |
|---|-------|--------|--------|
| 0 | Unify image ↔ comment | `build_dataset.py` | `data/intermediate/unified_dataset.csv` + `data/images_flat/` |
| 1 | Deterministic caption prep | `prepare_captions.py` | `data/intermediate/captions_prepared.csv` |
| 2 | Build controlled vocabulary | `build_vocabulary.py` | `data/vocabulary/*.txt`, `vocabulary.csv` |
| 3 | Audit vocabulary | `audit_vocabulary.py` | `data/vocabulary/_audit.txt` |
| 4 | Clean captions + qualitatize crust measures | `clean_captions.py` | `captions_pre.csv`, `captions_unique.csv` |
| 5 | Conservative noise drop | `find_useless_captions.py`, `drop_useless_captions.py` | `captions_to_rewrite.csv`, `captions_pre_filtered.csv` |
| 6 | LLM prompt design | `rewrite_prompt.py`, `render_prompts_for_review.py` | `data/prompts/*.md` |
| 7 | Pilot LLM run | `pilot_rewrite.py` | `data/reports/pilot_rewrites.csv` |
| 8 | Full batch LLM run | `rewrite_batch.py` | `data/rewrites/rewrites_*.csv` |
| 9 | Manual salvage of `NON_DESCRITTO` | `manual_salvage.py` | updated `rewrites_*.csv` |
| 10 | Broadcast + sentence form + deliverables | `broadcast_captions.py`, `make_sentence_form.py`, `build_final_outputs.py` | `data/final/*` |

Key ideas:

- **Phase 0 — join.** ~2,745 BMPs (organized year → session) are matched to
  comments from four Excel workbooks (2018–2021, each with different schema).
  Match is done at the **dairy level** on `(session_date, product_code)` because
  the data does not support a 1:1 wheel-level join. Each panelist comment is
  broadcast to all of that dairy's photographs for the day (a/b replicates ×
  Fetta/Grana views). Images are copied into `images_flat/` with collision-safe
  `folder__subfolder__file.bmp` names.
- **Phases 1–5 — deterministic cleaning.** Unicode normalization (NFC), typo /
  abbreviation maps, a custom Italian lemmatizer (standard NLP libraries
  mis-lemmatize the sensory lexicon), a controlled vocabulary built per
  attribute, and a **conservative** noise drop (only ~0.2% of unique captions
  removed). Crust-thickness measurements (`mm`/`cm`) are deterministically
  bucketed into qualitative bands. Captions are deduplicated for the LLM step
  (≈5× compression) and re-broadcast afterward.
- **Phases 6–9 — LLM rewriting.** One system prompt per attribute rewrites each
  unique caption into a consistent, attribute-anchored sentence, with a hard
  *zero-invention* rule and a `NON_DESCRITTO` escape for info-free input. A
  **pilot run** validates the prompt before the **full batch** (Anthropic Batch
  API, `claude-haiku-4-5`, 50% batch discount; ~$4.50 for the full batch,
  ~$5.60 across all LLM steps). A short **manual
  salvage** pass recovers ~178 captions the model over-conservatively flagged.
- **Phase 10 — finalize.** Rewritten captions are broadcast back to all matching
  rows; a deterministic regex transform adds a full-sentence form
  (`caption_sentence`, 100% template-matched); and three granularity levels of
  deliverable are written.

Full rationale for every decision (and the alternatives rejected) is in
[`reports/pipeline_phases_report.md`](reports/pipeline_phases_report.md) and the
per-phase files in [`reports/phases/`](reports/phases/).

### Final dataset (`data/final/`)

- `captions_final.csv` — full table, 38,437 rows × 18 columns (with full
  metadata: panelist, session date, dairy code, view, etc.).
- `image_caption_attribute.csv` — simplified 4-column table:
  `image_path, attribute, caption, caption_sentence`.
- `by_attribute/<Attribute>.csv` — per-attribute splits.
- `splits.json` — train/val/test split by `sample_id`, stratified by year.

Two caption forms per row:

- **`caption`** — compact, attribute-anchored: `"Profumo di panna."`. Best for
  per-attribute models.
- **`caption_sentence`** — full Italian sentence: `"Il formaggio ha un profumo
  di panna."`. Better for general decoders and for BLEU/METEOR/CIDEr.

## 4. Step 2 — Modeling

### Architectures

Six encoder–decoder architectures across two families (`training/models.py`):

| ID | Encoder | Decoder | Family |
|----|---------|---------|--------|
| `m1` | ResNet-50 (global pooled) | LSTM | A — from scratch |
| `m2` | ResNet-50 (spatial) | Transformer | A — from scratch |
| `m3` | ViT-B/16 | Transformer | A — from scratch |
| `m4` | ResNet-50 (global pooled) | GePpeTto (Italian GPT-2) | B — pretrained LM |
| `m5` | ResNet-50 (spatial) | GePpeTto | B — pretrained LM |
| `m6` | ViT-B/16 | GePpeTto | B — pretrained LM |

Each takes the paired **Fetta + Grana** views; the encoder concatenates the two
sets of visual tokens along the sequence dimension before the decoder.

Each architecture runs in two modes (`--finetune`):

- **frozen encoder** (default) — only the decoder + projection train;
- **end-to-end fine-tune** — encoder unfrozen with a differential learning rate.

So **6 architectures × 2 modes = 12 model runs** are *possible*. Models can also
be trained **per-attribute** (`--attributo Texture`) or **global**
(`--attributo all`).

> **Current eval scope.** The results below come from the subset actually
> trained and scored so far: **m1, m3, m6 in frozen-encoder mode** (per-attribute
> + global), plus **3 baselines** (`random`, `most_frequent`, `freq_weighted`).
> The remaining architectures (m2, m4, m5), all fine-tune runs, and the
> `retrieval` baseline are not yet scored.

Training (`training/train.py`) uses teacher forcing with weighted
cross-entropy, label smoothing (0.1), gradient clipping, an LR scheduler
(StepLR / cosine), and early stopping. Default decoding is nucleus sampling
(`top_p=0.9`, `temperature=0.7`); beam search is also available.

### Baselines

Four non-trained baselines (`training/baselines.py`) provide a floor:

1. `random` — a random training caption per test row;
2. `most_frequent` — always the most common training caption;
3. `freq_weighted` — sample captions weighted by frequency;
4. `retrieval` — nearest neighbor by ResNet-50 visual features (excludes the
   same `sample_id` to avoid panelist leakage). *Implemented in `baselines.py`
   but not yet scored — its predictions are absent from the current eval run.*

## 5. Evaluation

`eval_metrics/compute_metrics.py` scores predictions with eight complementary
metrics, each answering a different question:

| Metric | Question it answers |
|--------|---------------------|
| BLEU-1 / BLEU-4 | Does it reproduce the reference phrasing? |
| METEOR | Right words, including inflections/synonyms? |
| ROUGE-L | Right overall ordering of elements? |
| **CIDEr** | Does it nail the *salient* sensory terms (TF-IDF weighted)? |
| BERTScore-F | Did it capture the concept, even when rephrasing? |
| **Vocab Conformance** | Does it speak with the certified domain terminology? (custom) |
| **CLIPScore** | Is the caption appropriate for the *image* (ignores the reference)? |

Headline findings (details in
[`eval_metrics/METRICS_REPORT.md`](eval_metrics/METRICS_REPORT.md)):

- Per-attribute models are strong on text metrics (BLEU-4 ≈ 0.30–0.45); a single
  **global** model collapses (BLEU-4 ≈ 0.13) — specialization wins.
- BLEU-1 alone is misleading: the constant `most_frequent` baseline scores the
  highest BLEU-1 of all by always emitting the same template.
- **CLIPScore is nearly identical across trained models and baselines** — with a
  frozen encoder the models do language modeling over the caption distribution
  rather than truly grounding in the image. The natural next experiment is
  encoder fine-tuning, then re-measuring CLIPScore.

## 6. How to reproduce

### Prerequisites

- Python 3.10+
- For Step 1 (LLM rewriting): an Anthropic API key in `ANTHROPIC_API_KEY` (or
  `CLAUDE_KEY`).
- For Step 2: PyTorch (CUDA GPU strongly recommended; CPU/MPS supported but
  slow). `transformers` for the GePpeTto decoder.
- Raw inputs in place: the Excel workbooks under `data/GT commenti liberi/` and
  the BMP tree under `data/TrentinGrana/`.

### Step 1 — rebuild the dataset

Run the pipeline scripts in order from the project root:

```bash
python scripts/build_dataset.py            # phase 0  — join images + comments
python scripts/prepare_captions.py         # phase 1  — deterministic prep
python scripts/build_vocabulary.py         # phase 2  — controlled vocabulary
python scripts/audit_vocabulary.py         # phase 3  — vocabulary audit
python scripts/clean_captions.py           # phase 4  — clean + qualitatize measures
python scripts/find_useless_captions.py    # phase 5a — survey noise
python scripts/drop_useless_captions.py    # phase 5b — conservative drop
python scripts/render_prompts_for_review.py # phase 6 — render prompts (free, offline)
python scripts/pilot_rewrite.py            # phase 7  — pilot LLM run  (needs API key)
python scripts/rewrite_batch.py            # phase 8  — full batch run (needs API key)
python scripts/manual_salvage.py           # phase 9  — manual salvage
python scripts/broadcast_captions.py       # phase 10 — broadcast rewrites
python scripts/make_sentence_form.py       # phase 10 — add caption_sentence
python scripts/build_final_outputs.py      # phase 10 — write deliverables
```

This produces `data/final/captions_final.csv` and the other deliverables.
`data/images_flat/` (~6 GB) is regenerated by `build_dataset.py` and is
gitignored.

> If you only want to train, you can skip Step 1: the deliverables in
> `data/final/` are committed. You still need `data/images_flat/`, which you
> regenerate by running `build_dataset.py` over the raw `data/TrentinGrana/`
> tree.

### Step 2 — train and evaluate

**1. Bridge the dataset into the training format** (creates
`dataset_captioning.csv` + `splits.json`):

```bash
python -m training.prepare_data
```

**2. Train a model.** Examples:

```bash
# per-attribute, frozen encoder
python -m training.cli --model m1 --attributo Texture

# global model, all attributes
python -m training.cli --model m2 --attributo all --epochs 50

# evaluate an existing checkpoint only
python -m training.cli --model m3 --attributo Profumo --eval-only

# end-to-end fine-tune (encoder unfrozen, differential LR)
python -m training.cli --model m6 --attributo all --finetune
```

Useful flags: `--caption-column {caption,caption_sentence}`, `--resume`,
`--decode-strategy {beam,nucleus}`, `--beam-size`, `--top-p`, `--temperature`.
Checkpoints and `predictions.csv` are written under
`training/runs/<model>/<attribute>/`.

For Kaggle GPU kernels, use the batch entrypoint:

```bash
python -m training.kaggle_run --models m1 m2 m3 --attributo all
```

**3. Run the baselines:**

```bash
python -m training.run_baselines --attributo all
```

**4. Score everything.** The evaluation harness has its own isolated venv:

```powershell
# one-time: create venv + install deps
.\eval_metrics\setup.ps1

# one-time: attach image_path to predictions (needed for CLIPScore)
.\eval_metrics\.venv\Scripts\python.exe eval_metrics\add_image_paths.py

# compute all 8 metrics over the predictions/ folder
.\eval_metrics\.venv\Scripts\python.exe eval_metrics\compute_metrics.py predictions --images-root .
```

Useful flags: `--no-bertscore` (skip BERT download), `--no-clipscore` (text
metrics only, much faster), `--out <path.csv>`. Output is a table plus
`eval_metrics/metrics_summary.csv`.
